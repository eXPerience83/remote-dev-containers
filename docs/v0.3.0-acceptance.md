The alternative `/root/.gemini/antigravity/mcp_oauth_tokens.json` does not exist in this runtime. **Actual survival across container recreation is not yet verified**; private backup/rollback remain required.

- Host ACL audit, private backup/rollback and AGY OAuth persistence after container recreation are pending; see [#95](https://github.com/eXPerience83/remote-dev-containers/issues/95) and [#346](https://github.com/eXPerience83/remote-dev-containers/issues/346).

## Before touching TrueNAS

- Select a successfully published Edge **full source SHA and immutable OCI digest**. Require Build AMD64 and Publish Edge AMD64 success for the **same SHA**; never combine CI evidence from different revisions.
- Existing hermetic CI cannot prove real Codex/Antigravity interaction or patch status for the exact Chromium archive.
- **Do not recreate or update active TrueNAS sessions without a maintenance window approved by the operator.** Save previous digest, private role-specific backups and App/Compose settings; retain a tested rollback route.
- Never post keys, private TOML/JSON, credentials, sensitive screenshots or user-specific paths in public evidence. Record only run URLs, SHA/digest, redacted PASS/FAIL/SKIP and findings.
- Keep role-local credentials and MCP entries independent; no launcher exposure.
- **Security gate #320:** Chromium Headless Shell `158.0.8127.18` is not proven patched for exploited CVE-2026-125350. **Only controlled loopback fixture pages** may be used for any browser trials; avoid external/untrusted sites. No general-browsing stable release with this unresolved.
- `stable` and `latest` remain untouched until full acceptance.

## 1. Real Context7 acceptance — #95

In the **Codex role terminal** run read-only diagnostics:
```sh
remote-dev-version --check
remote-dev-context7 status --menu
remote-dev-context7 plan
remote-dev-doctor
codex mcp list
```

In the **Antigravity role terminal**:
```sh
remote-dev-version --check
remote-dev-context7-antigravity status --menu
remote-dev-context7-antigravity plan
remote-dev-doctor
```

**PASS:** diagnostics do not write or send network requests; each role sees only its own state; unrelated Playwright/OpenAI Developer Docs/custom MCP registrations and private keys are unchanged. A corrupt/ambiguous/user-owned registration fails closed with redacted messages.

After taking private backups and checking `plan`, only for **explicitly eligible** registrations with operator approval, reinstall Context7 within the matching role:
```sh
# Codex role ONLY, when eligible:
remote-dev-context7 reinstall --yes
# Antigravity role ONLY, when eligible:
remote-dev-context7-antigravity reinstall --yes
```

**SKIP rather than force** if an Antigravity entry has custom options/credentials, or either provider reports ambiguous scope. Verify idempotence, preservation of all other MCPs, private backups and rollback, no cross-role key copying and no automatic startup changes.

In a **real Codex session**, check `/mcp` and request an innocuous public-documentation question that triggers an **actual Context7 tool call**; confirm other MCPs still work. In a **real `agy` session**, use `/mcp` and perform an equivalent real Context7 tool invocation, separately checking Playwright. A `test --yes` endpoint ping does **not** prove real agent-side MCP use. Never send project secrets to Upstash. Verify agent login/session remains usable when Context7 is unavailable.

**Close #95** only after both real-agent MCP calls, role persistence and rollback are evidenced and the independent human hosted-service/privacy disposition is recorded in #53.

## 2. Playwright MCP / Chromium — #320

- On the exact reviewed source SHA, require `scripts/browser-mcp-smoke.mjs` for real MCP stdio, tool listing, loopback HTTP/DOM, JS, WebSocket, screenshot and close; plus `scripts/test-browser-config.py`, `scripts/test-browser-sandbox.py`, UID/NoNewPrivs/Landlock/guardian tests, notices, SBOM and Trivy.
- In each **real agent session**, use **only a local controlled `127.0.0.1` fixture**: verify the `playwright` MCP is registered, visit the local page, evaluate JavaScript, capture a screenshot, and close. Ensure other MCP config survives; no exposed MCP listener ports or abandoned private profiles.
- Before any external navigation/general production claim, prove the **exact binary** contains the CVE-2026-125350 fix (or is unaffected), or update the **official matched set** `@playwright/mcp` → `playwright-core` → Chromium Headless Shell. Review AMD64/ARM64 npm/ZIP hashes, notices, sandbox, runtime smoke and exact-source publication. Do not mix arbitrary ZIP/browser versions or infer patch status from green Trivy.
- **NO GO for a stable release claiming general browsing while #320 remains unresolved.**

## 3. CI and stable v0.3.0 cut

- Record #327 Trivy/cache improvements from #342/#343 and successors; measure repeated runs without treating saved substep time as guaranteed end-to-end wall-clock savings. Preserve strict vulnerability gate and role isolation snapshots.
- With Context7 accepted, Chromium #320 resolved, and a dated #53 human privacy/license decision: freeze reviewed `main` SHA, require same-SHA Build + Edge publication, and perform the TrueNAS acceptance and rollback evidence above.
- Only then open a dedicated **version-cut PR** to set `BASE_VERSION` and both Dockerfile local defaults to `0.3.0`, date the changelog and sync source/release docs. **Do not bump the version during preflight.**
- After exact-head review/CI and merge, tag the accepted `main` commit `v0.3.0`; require independent stable publisher gates (smoke, notices, both SPDX, critical CVE gate, exact OCI digest promotion). Verify `stable`, `stable-amd64` and `latest` point to the same approved digest, and no edge/dev publication has changed `latest`.
- Complete the [stable release checklist](releases.md#stable-release-checklist): role/private state persistence, trusted LAN-only routing, authentication, project Resume and host ACL acceptance.
