## 3. CI and stable v0.3.0 cut

- Record #327 Trivy/cache improvements from #342/#343 and successors; measure repeated runs without treating saved substep time as guaranteed end-to-end wall-clock savings. Preserve strict vulnerability gate and role isolation snapshots.
- With Context7 accepted, Chromium #320 resolved, and a dated #53 human privacy/license decision: freeze reviewed `main` SHA, require same-SHA Build + Edge publication, and perform the TrueNAS acceptance and rollback evidence above.
- Only then open a dedicated **version-cut PR** to set `BASE_VERSION` and both Dockerfile local defaults to `0.3.0`, date the changelog and sync source/release docs. **Do not bump the version during preflight.**
- After exact-head review/CI, merge the version-cut PR. **From that merged `main` SHA**, require successful Build and Publish Edge, record the immutable OCI digest, and complete operator-approved TrueNAS acceptance and rollback **on that exact digest**. Pre-version-cut acceptance on an earlier SHA does not substitute for the final acceptance.
- **Before tagging**, complete the [stable release checklist](releases.md#stable-release-checklist): role/private state persistence, trusted LAN-only routing, authentication, project Resume and host ACL acceptance, plus the changelog, third-party decision and all required release gates.
- Once the source SHA and TrueNAS Edge acceptance are signed off, tag the reviewed merged `main` commit `v0.3.0`. The stable publisher reconstructs a **distinct stable candidate** from that SHA and, before moving tags, runs exact-manifest smoke/notices/isolation and produces base/final SPDX and Trivy evidence with a critical-vulnerability gate. The `v0.3.0`, `stable`, `stable-amd64` and `latest` aliases must point to the **same validated stable OCI index digest** (not necessarily the Edge index digest); confirm that the index's linux/amd64 child matches the exact runtime manifest used for smoke and Trivy/SPDX. The index digest and tested child digest differ. Verify deployed stable separately on TrueNAS after publication before closing #346.
