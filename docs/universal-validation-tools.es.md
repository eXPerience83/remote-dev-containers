# Herramientas de validación local PR2 (#121)

PR2 #281 está **fusionada y publicada en edge AMD64** desde el 18/10/2026. En su integración original añadió seis comandos a PR1 (47 → 53): Ruff **0.17.1**, pytest **9.1.1**, pre-commit **4.7.0**, yq de Mike Farah **4.54.1**, shfmt **3.14.1** y actionlint **1.7.12**. Publicar edge no equivale a una versión estable ni a soporte de ejecución ARM64.

## Instalación y precedencia del proyecto

Tras la [PR #294](https://github.com/eXPerience83/remote-dev-containers/pull/294), `main` utiliza Ruff **0.17.3**, pytest **9.1.1**, pre-commit **4.7.0** y Python administrativo **3.14.10**; Python **3.15.2** sigue disponible por selección explícita de proyecto. Las tres CLI Python usan identidades explícitas `pypi:` y `python = "3.14.10"` en mise. El formato 3 de `mise.lock` referencia por SHA-256 los grafos nativos uv de `.mise/locks`, con versiones transitivas exactas, marcadores y hashes de ruedas oficiales PyPI. La instalación congelada, sin compilar distribuciones fuente, crea entornos CLI separados e inmutables. No añade paquetes al site-packages de Python 3.14 ni 3.15. Estas CLI no proporcionan dependencias ni plugins del proyecto: para su validación final prevalece el entorno declarado, por ejemplo `.venv/bin/python -m pytest`. Una versión solicitada ausente debe fallar sin instalación automática ni fallback. No se activa `.venv` automáticamente.

Los comandos nativos conservan identidades cortas mise y los backends revisados `aqua:mikefarah/yq`, `aqua:mvdan/sh` y `aqua:rhysd/actionlint`. El lock generado registra cosign para yq y attestations GitHub para actionlint, verificadas al generarlo con `locked_verify_provenance=true`. shfmt tiene checksums oficiales, sin atribuirle procedencia criptográfica adicional. Se bloquean artefactos Linux AMD64 y ARM64. No se incorpora otra implementación de yq, pyflakes, shims Corepack ni herramientas adicionales.

Arranque, health checks y Doctor no instalan ni descargan herramientas. Base Verify usa `/`; Doctor consume el inventario común para roles de desarrollo y exime al launcher. Las reglas globales existentes informan a ambos agentes de disponibilidad y precedencia. Se conservan raíz de solo lectura, `/tmp noexec`, `$TMPDIR` ejecutable y privado y `PRE_COMMIT_HOME` separado por rol. Una ejecución explícita de pre-commit puede descargar hooks configurados por el proyecto; la prueba sin red usa únicamente un hook local `language: system`.

## Mantenimiento y licencias

`scripts/regenerate-mise-lock.sh` exige el mise fijado y uv exacto (`UV_BIN`), aísla estado y valida los grafos antes de publicar el lock. Conserva directorios anteriores para no romper el lock previo ante un fallo. Los grafos acompañan a ambos nombres del lock dentro de la imagen. El actualizador upstream mantiene las seis líneas estables, el resolver verificado, grafos, inventario y licencias mediante una PR revisada sin fusión automática.

`scripts/sync-python-cli-notices.py --write` descarga ruedas oficiales verificadas con los hashes comprometidos y conserva sus licencias/notices reales, incluidas las ruedas de semillas redistribuidas en virtualenv. La comprobación sin red vincula evidencia y artefactos. El inventario incluye conservadoramente todos los paquetes del grafo, incluido colorama condicional, sin afirmar que todos se instalen en Linux. Siguen siendo obligatorios SPDX, Trivy y el bloqueo de CRITICAL corregibles. La evidencia complementa las limitaciones de detección del escáner; la aceptación específica de distribución/licencias de PR2 fue registrada por el propietario en #53 el 18/10/2026; #53 sigue abierto para auditorías periódicas y cambios futuros.

## Validación y evidencias

`test-validation-tools.sh` prueba los seis comandos sin red en contenedores de solo lectura y sin capacidades, para fixtures Codex y Antigravity, desde CWD neutro y proyecto Python 3.15. Comprueba lint/formato Ruff, tests pytest reales y su intérprete aislado 3.14, hooks locales pre-commit, transformación yq, formato shfmt, workflows válidos/inválidos, site-packages globales limpios, venv explícito del proyecto y estabilidad del almacén inmutable. Las pruebas mise añaden ausencia de versión y ausencia de fallback para yq. Los fixtures prueban el entorno de procesos; no sustituyen tareas de modelos autenticados ni aceptación externa en TrueNAS.

La generación bloqueada con mise y uv fijados cubre AMD64 y ARM64, aunque solo AMD64 tiene ejecución runtime soportada. **La CI definitiva de PR2** superó instalación Docker limpia, funcionamiento de las seis CLI, selección de Python 3.15, separación de roles y conservación del almacén inmutable. El incidente de estado heredado en la prueba local no se reprodujo en CI y no motivó ninguna relajación de seguridad.
