## Evidencia de TrueNAS disponible (14-11-2026)

- **PASS de uso real**: Codex y Antigravity invocaron herramientas Context7 `resolve-library-id`/`query-docs` para documentación pública de `/psf/requests`.
- **PASS de cuenta Codex**: clave almacenada válida en la API de uso (HTTP 200), incremento agregado de +2 solicitudes tras dos llamadas MCP; atribución exclusiva no demostrada. `Not logged in` se refiere al OAuth nativo, no invalida esa clave.
- **PASS de login interactivo AGY**: `/mcp → context7 → Authenticate` terminó en `Authentication successful!`. **No es aún PASS de persistencia** tras recreación. El proveedor indica `~/.gemini/antigravity/mcp_oauth_tokens.json`, no cubierto por los mounts actuales de Compose.
- **PASS funcional Playwright real local**: ambos agentes navegan solo a `127.0.0.1`, leen DOM, ejecutan JS, obtienen captura y limpian. Sigue **NO GO para sitios externos/no confiables** por #320.
- La auditoría de ACL del host, el rollback y la conservación de OAuth tras recreación siguen pendientes; ver [#95](https://github.com/eXPerience83/remote-dev-containers/issues/95) y [#346](https://github.com/eXPerience83/remote-dev-containers/issues/346).

## Reglas de ejecución

- **Primero** congelar una Edge publicada identificada por SHA completo de `main` y digest OCI exacto. Requerir **Build AMD64 y Publish Edge AMD64 verdes para ese mismo SHA**. Una imagen/CI de otro commit no vale.
- Las pruebas de integración del repositorio no acreditan sesiones reales de Codex/Antigravity ni que Chromium esté parcheado.
- **No actualizar ni recrear TrueNAS mientras haya sesiones activas no preservadas.** Antes de actualizar, registrar digest anterior, configuración App/Compose y copias privadas de configuración/estado por rol; conservar vía de rollback. La aceptación requiere permiso del operador.
- No subir credenciales, TOML/JSON privados, claves API, capturas sensibles ni rutas personales a issues o logs públicos. Registrar solo SHA/digest, comandos, resultado PASS/FAIL/SKIP y motivos redactados.
- No compartir configuraciones, clave Context7 ni estado entre Codex y Antigravity. El launcher no recibe datos de agentes.
- **Seguridad bloqueante:** #320 sigue abierto. La revisión Chromium Headless Shell `158.0.8127.18` no tiene parche acreditado para CVE-2026-125350. La ejecución de pruebas del navegador debe limitarse a **fixture local controlado** hasta que exista una pareja oficial MCP/Core/Chromium parcheada y validada (o prueba sólida de no afectación). No navegar a sitios externos/no confiables.
- Mantener `stable` y `latest` intactos hasta aceptación completa y publicación por tag exacto.

## 1. Context7: pruebas en sesiones reales

### A. Diagnósticos pasivos (sin modificación ni red del gestor)

Ejecutar en **terminal de cada rol**, no desde el launcher. Comparar estado previo y posterior de archivos privados sin publicar su contenido. Las rutas de configuración se obtienen de [Context7 Codex](context7-codex.es.md) y [Antigravity](context7-antigravity.es.md).

En **Codex**:
```sh
remote-dev-version --check
remote-dev-context7 status --menu
remote-dev-context7 plan
remote-dev-doctor
codex mcp list
```

En **Antigravity**:
```sh
remote-dev-version --check
remote-dev-context7-antigravity status --menu
remote-dev-context7-antigravity plan
remote-dev-doctor
```

**PASS:** comandos pasivos no cambian configuración, claves ni otros MCP; los errores describen estados incompletos sin revelar secretos; Codex y AGY solo ven su estado privado. Una configuración personalizada debe reportarse como no gestionada o bloqueada, nunca sobrescribirse.

### B. Reinstalación opt-in (solo tras respaldo privado)

Revisar `plan` y la preimagen. Si el ámbito es ambiguo o Antigravity tiene opciones personalizadas/credenciales, registrar **SKIP bloqueado** y **no forzar la reinstalación**. Solo para una entrada elegible, y con aprobación explícita del operador:

```sh
# Ejecutar SOLO dentro de Codex cuando plan lo permita:
remote-dev-context7 reinstall --yes
# Ejecutar SOLO dentro de Antigravity cuando plan lo permita:
remote-dev-context7-antigravity reinstall --yes
```

**PASS:** solo se reconstruye `context7` de ese rol; permanecen Playwright, `openaiDeveloperDocs`, otros MCP, credenciales privadas, proyectos y sesión. Los comandos son idempotentes; las copias y el rollback son verificables. Ninguna prueba justifica el borrado global del archivo MCP.

### C. Herramientas reales del agente

En **Codex** usar `/mcp` y pedir una consulta inocua de documentación pública que obligue a invocar una herramienta de Context7; verificar en el resultado que hubo **una llamada real** a Context7, no una respuesta general del modelo. Probar también que `openaiDeveloperDocs` sigue registrado y operativo.

En **Antigravity** abrir una sesión `agy`, consultar `/mcp` y pedir una pregunta pública análoga con uso real de herramientas Context7. Verificar por separado el MCP Playwright y las entradas ajenas.

`remote-dev-context7-antigravity test --yes` y la prueba de conectividad de Codex son verificaciones **explícitas de endpoint**, no sustituyen estas llamadas reales. No enviar código del proyecto ni secretos a Upstash. Registrar el comportamiento ante proveedor no disponible sin romper el inicio o las sesiones.

**Cierre #95:** ambas llamadas reales PASS, otros MCP intactos, persistencia y rollback por rol probados y decisión humana específica de uso/privacidad documentada en #53. La aceptación experimental de Antigravity no equivale a soporte oficial del proveedor.

## 2. Playwright MCP / Chromium

- **En CI sobre el SHA exacto:** comprobar el resultado de `scripts/browser-mcp-smoke.mjs` (stdio MCP, `tools/list`, HTML/DOM, JS, WebSocket y captura), de `scripts/test-browser-config.py`, `scripts/test-browser-sandbox.py` y de Build/avisos/SPDX/Trivy. Las pruebas de Landlock/guardian/UID/NoNewPrivs no se omiten.
- **Con agentes reales, y solamente una web local propia de pruebas:** confirmar que `playwright` aparece en Codex y `agy /mcp`, que una navegación HTTP sobre `127.0.0.1` alcanza la página local, y que JavaScript y captura funcionan desde cada agente. Verificar no alteración de otros MCP, ausencia de puertos nuevos del servidor MCP, perfil efímero y limpieza al salir.
- **Bloqueo para navegación externa/estable:** acreditar la corrección de CVE-2026-125350 para el binario exacto o instalar un conjunto **oficialmente correspondiente** `@playwright/mcp` → `playwright-core` → Chromium Headless Shell. Verificar hashes npm/ZIP AMD64 y ARM64, notices, regresiones de aislamiento, funcionalidad y nueva Edge exacta. No sustituir solo `browserVersion`/ZIP.
- Un Trivy verde **no** es prueba del parche del ZIP Chromium. Si #320 sigue abierto, **NO GO para incluir navegación general en v0.3.0 estable**.

## 3. CI y transición a stable v0.3.0

- Documentar los PR #342/#343 y siguientes (#327), medir varios runs en vez de prometer reducción de reloj por una muestra. No relajar el veto de vulnerabilidades críticas ni eliminar snapshots de aislamiento.
- Una vez aprobado #95 y resuelto #320, congelar commit revisado de `main`; comprobar Build y Publish Edge **sobre exactamente ese SHA**, publicar/identificar digest, guardar digest previo y completar la aceptación TrueNAS anterior.
- Revisión humana de términos, privacidad y distribución #53; comprobar licencias, avisos, inventario y SBOM. El informe automatizado no constituye una decisión legal.
- Preparar **PR específico de versión** cuando los bloqueos estén resueltos: cambiar `BASE_VERSION` y defaults de ambos Dockerfiles a `0.3.0`, fechar `CHANGELOG.md`, reconciliar `PROJECT_STATUS.md` y documentación de canales. No cambiar la versión ahora.
- Tras CI y revisión exact-HEAD, fusionar; crear el tag SemVer exacto `v0.3.0` **solo** en el commit aceptado de `main`. Requerir workflow estable independiente con smoke, notices, dos SPDX, Trivy crítico, verificación de digest y promoción `stable = stable-amd64 = latest` al digest evaluado. Confirmar `edge` y `dev` no modifican `latest`.
- Antes de cerrar aceptación, verificar login/Resume, persistencia, aislamiento de los tres roles, permisos/ACL, red privada y funcionamiento básico según [checklist estable](releases.es.md#checklist-de-release-estable).
