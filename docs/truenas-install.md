# TrueNAS SCALE: installation, persistence, and upgrades

> **Beta acceptance before v0.1.1:** source `0.1.1-beta.1` is not a published tag. Pin a successfully published `edge-amd64` image by digest, retain the old digest for rollback and follow the [beta acceptance checklist](releases.md) before considering stable.

This guide describes the **experimental edge** channel; no stable release exists yet. The canonical stack definition is [compose/truenas.yml](../compose/truenas.yml). See the [advanced TrueNAS runbook](truenas-antigravity-validation.md) and [host ACL contract](truenas-acl-contract.md) for deeper validation.

## 1. Root dataset and safety

**New installation:** create one administrator-owned root dataset in the TrueNAS UI, e.g. **Pool1/remote-dev**, mounted at **/mnt/Pool1/remote-dev**, using the **Generic / POSIX ACL** preset. Only this root normally needs to be a ZFS dataset. The child workspace/state paths will be ordinary directories generated by bootstrap, not additional entries in the ZFS datasets view. Deliberately created child datasets are supported and never rewritten.

**Existing installation:** preserve the root and its data. Record the old immutable image digest and save a **sanitized** current Custom App YAML before changing anything. If the root uses the Apps/NFSv4 preset, do not recursively change ACLs, modes or ownership: see the [ACL audit/migration guide](truenas-acl-contract.md). Passing a path preflight does not prove inherited NFSv4 permissions are private.

Protected agent endpoints use WEB_PASSWORD in App configuration; no password-secret directory is created. The launcher remains password-free and must be exposed only on a trusted LAN/private mesh.

## 2. Obtain host scripts matching the exact image revision

Run the following in a **TrueNAS host Bash shell**, not inside an agent. Always pin the selected image by digest, even when you already have a matching checkout. The no-checkout path also downloads the revision-matched Compose YAML, not only the scripts.

~~~bash
set -euo pipefail
IMAGE=ghcr.io/experience83/remote-dev:edge-amd64
ROOT=/mnt/Pool1/remote-dev

sudo docker pull "$IMAGE"
IMAGE_REPO=ghcr.io/experience83/remote-dev
PINNED_IMAGE=""
while IFS= read -r repo_digest; do
  case "$repo_digest" in
    "$IMAGE_REPO"@sha256:*) PINNED_IMAGE="$repo_digest"; break ;;
  esac
done < <(sudo docker image inspect "$IMAGE" \
  --format '{{range .RepoDigests}}{{println .}}{{end}}')
[[ "$PINNED_IMAGE" =~ ^ghcr\.io/experience83/remote-dev@sha256:[0-9a-f]{64}$ ]] || {
  echo 'Missing or invalid registry digest: do not deploy a mutable tag' >&2
  exit 1
}
REV="$(sudo docker image inspect "$PINNED_IMAGE" \
  --format '{{ index .Config.Labels "org.opencontainers.image.revision" }}')"
[[ "$REV" =~ ^[0-9a-f]{40}$ ]] || { echo 'Invalid source revision' >&2; exit 1; }

SETUP="$(mktemp -d /tmp/remote-dev-setup.XXXXXXXX)"
mkdir -p "$SETUP/scripts/lib" "$SETUP/compose"
for path in \
  scripts/init-data-layout.py \
  scripts/preflight-data-layout.py \
  scripts/truenas-acl-audit.py \
  scripts/lib/data_layout.py \
  compose/truenas.yml; do
  curl -fsSL --retry 2 \
    "https://raw.githubusercontent.com/eXPerience83/remote-dev-containers/$REV/$path" \
    -o "$SETUP/$path"
done
echo "Source revision: $REV"
echo "Immutable image: $PINNED_IMAGE"
echo "Revision-matched files: $SETUP"
~~~

Scripts **and the original Compose template** are fetched over HTTPS from the immutable source revision read from the **digest-pinned** image, not a floating branch. Keep this same Bash shell session open (it holds `SETUP`, `REV`, and `PINNED_IMAGE`). Inspect scripts before running them with administrator privileges.

## 3. Directly create persistent directories

Confirm ROOT **already exists and is the correct dataset**. Bootstrap does not create ROOT or ZFS datasets; it rejects symlinks and non-directory components, is idempotent, and never deletes or recursively rewrites existing permissions or contents.

For the reference YAML with Codex and optional Antigravity:

~~~bash
sudo python3 -B "$SETUP/scripts/init-data-layout.py" --root "$ROOT" --include-antigravity
sudo python3 -B "$SETUP/scripts/preflight-data-layout.py" --root "$ROOT" --include-antigravity
sudo python3 -B "$SETUP/scripts/truenas-acl-audit.py" --root "$ROOT" --include-antigravity
~~~

If you already have an exactly matching checkout, instead run:

~~~bash
sudo python3 -B scripts/init-data-layout.py --root /mnt/Pool1/remote-dev --include-antigravity
sudo python3 -B scripts/preflight-data-layout.py --root /mnt/Pool1/remote-dev --include-antigravity
sudo python3 -B scripts/truenas-acl-audit.py --root /mnt/Pool1/remote-dev --include-antigravity
~~~

Omit **--include-antigravity** throughout only after removing the Antigravity service and bind mounts from your customized YAML. [scripts/lib/data_layout.py](../scripts/lib/data_layout.py) is the single authoritative source of required directories:

~~~text
/mnt/Pool1/remote-dev/
  workspaces/codex/
  workspaces/antigravity/
  state/codex/{agent,runtime,mise,gh,git,ssh}/
  state/antigravity/{bin,runtime,vendor,config,mise,gh,git,ssh}/
~~~

New workspaces use mode 0755; private state leaf directories use 0700, and structural parents use 0755. Existing paths (including any child datasets) are never rewritten. Do not recursively chmod/chown the tree or mount the parent data root in an agent. Preflight verifies paths; the read-only host ACL audit separately checks the Generic/POSIX privacy contract. None of these scripts creates passwords or credentials.

## 4. Configure YAML and deploy

Use **`$SETUP/compose/truenas.yml`** downloaded from the same `REV` as the image and scripts. Generate a separate digest-pinned copy, leaving the source template unchanged:

~~~bash
SOURCE_COMPOSE="$SETUP/compose/truenas.yml"
PINNED_COMPOSE="$SETUP/truenas-pinned.yml"
[[ -f "$SOURCE_COMPOSE" ]] || { echo 'Missing source Compose file' >&2; exit 1; }
[[ "$(head -n 1 "$SOURCE_COMPOSE")" == 'x-remote-dev-image: &remote-dev-image '* ]] || {
  echo 'Unexpected Compose image anchor; inspect the source template' >&2
  exit 1
}
{
  printf 'x-remote-dev-image: &remote-dev-image %s\n' "$PINNED_IMAGE"
  tail -n +2 "$SOURCE_COMPOSE"
} > "$PINNED_COMPOSE"
echo "Edit and paste this pinned Custom App YAML: $PINNED_COMPOSE"
~~~

Use **`PINNED_COMPOSE`** in the Custom App editor, not the mutable-tag template. This replaces the **single shared** `x-remote-dev-image` anchor so launcher, Codex, and optional Antigravity all use the same immutable `ghcr.io/experience83/remote-dev@sha256:…` reference. Before saving the Custom App:

- Replace example bind IP 192.168.1.10 with the intended LAN/Tailscale IP.
- Change every /mnt/Pool1/remote-dev bind source if ROOT differs.
- Set non-empty, single-line WEB_PASSWORD values for Codex and enabled Antigravity. Reuse is currently permitted.
- Confirm that all enabled services use **the same digest-pinned image anchor**; inspect the saved YAML again because TrueNAS may rewrite Compose interpolation and comments.
- Preserve read-only container roots, narrow mounts/capabilities, and ports 7680/7681/7682 on trusted networks only. Do not mount a Docker socket.

Host administrators can read the configured passwords. Sanitize YAML exports and screenshots.

## 5. Accept PR2 on the running stack

After updating without deleting persistent paths:

~~~bash
set -euo pipefail
CHECK_ANTIGRAVITY=0  # Change to 1 when the optional service is deployed
containers=(codex-remote-dev)
if [[ "$CHECK_ANTIGRAVITY" == "1" ]]; then
  containers+=(antigravity-remote-dev)
fi
for container in "${containers[@]}"; do
  sudo docker exec "$container" remote-dev-version --check
  sudo docker exec "$container" remote-dev-base-verify
  [[ "$(sudo docker exec "$container" stat -c '%u:%g %a' /usr/share/doc/remote-dev)" == '0:0 755' ]] || {
    echo "ERROR: $container has an unsafe or unreadable notice directory" >&2
    exit 1
  }
  sudo docker exec "$container" remote-dev-notices --check
  sudo docker exec "$container" /bin/bash -c \
    'set -euo pipefail; cd / && for tool in ruff pytest pre-commit yq shfmt actionlint; do "$tool" --version; done'
done
~~~

In the image containing #285, the notices directory must be `root:root 0755` and `remote-dev-notices --check` must pass **without adding `DAC_READ_SEARCH`, `DAC_OVERRIDE` or other capabilities**. If it fails, recheck the deployed image digest; do not relax `cap_drop: [ALL]` or alter host ACLs to mask the problem.

This defaults to **Codex-only**. Set `CHECK_ANTIGRAVITY=1` **when Antigravity is enabled** so its checks are not silently omitted. Base Verify checks the **53-command** canonical inventory from a neutral directory; the loop resolves the six new CLIs directly. CI already exercises the actual tools under both hardened role fixtures, but authenticated live-agent acceptance remains separate.

Open the launcher at **http://PRIVATE-TRUENAS-IP:7680**, enter enabled agent terminals and **confirm old sessions resume**. For an image built from the exact reviewed [PR #294 source revision](https://github.com/eXPerience83/remote-dev-containers/commit/03e7c650828f47482e12b568f4a6127e658ed1d6), the default is Python **3.14.10** and the optional project-selected runtime is **3.15.2**. Later source revisions may use newer patches: compare the deployed image's exact source SHA with its matching `versions.env`, rather than assuming a mutable `edge` tag has moved. Python 3.14 should remain the default; Python 3.15 is selected only in explicitly compatible projects. Do not mutate real project config just to prove a version. Check Doctor, private mounts and isolation without disclosing secrets.

Record only sanitized SHA/digest and outcomes or errors in [#121](https://github.com/eXPerience83/remote-dev-containers/issues/121). Keep that issue open until genuine host acceptance.

## 6. Upgrade, rollback and cleanup

For upgrades, save old image digest and sanitized YAML, verify green edge workflows, pull the new edge, record the new **RepoDigest** and source `REV`, download its matched Compose template, regenerate the digest-pinned copy as in section 4 and recreate with identical bind mounts and previously documented host-specific settings. Verify effective SHA/digest and session persistence. For rollback, restore the old image digest **without deleting persistent state**; rolling back data needs a separate plan.

Remove only the temporary SETUP helper directory when finished, never ROOT or credentials. Edge tags are mutable; **latest** is reserved for stable, not experimental edge.
